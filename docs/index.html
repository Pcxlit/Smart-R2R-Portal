What Smart R2R Portal aims to be

The full platform proposed for this course project. Not all of it is built yet — see Progress for what's actually done.

a

Verified repair directory

Independent repair shops register and list verified profiles with upfront pricing.

b

Repair request & tracking

Submit a repair request and track its status in real time, from drop-off to completion.

c

RAG repair assistant

Ask about a laptop issue and get an answer sourced from real repair guides.

d

Reparability profiles

Each device scored on how easy it is to repair, based on parts and guide availability.

How the RAG pipeline works

The retrieval module Punya is building, end to end.

01

Ingest repair guides

Load source documents — currently the hinge repair and battery replacement placeholders.

02

Chunk & embed

Split into chunks and embed locally with sentence-transformers (all-MiniLM-L6-v2) — no external API keys needed.

03

Store in ChromaDB

Deterministic upsert IDs mean re-ingesting the same source never creates duplicate chunks.

04

Retrieve

A query is matched against stored embeddings; each result carries source metadata for relevance evaluation.

05

Generate Coming soon

An LLM will synthesize a final answer from retrieved chunks, once retrieval quality is validated.

06

Log & measure

Per-query latency is logged against the Time-to-Answer metric from the proposal.
